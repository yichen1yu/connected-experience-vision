I found two related KB articles for resolving dependency conflicts with custom kernel modules during OpenSSL updates:
📄 KB#7045231 — Resolving OpenSSL dependency conflicts with custom kernel modules ✅ Verified
When a custom kernel module links against libssl or libcrypto, updating OpenSSL can fail with an unresolved symbol error. To resolve:

1. Run rpm -qa --last | grep kernel to identify the custom module
2. Temporarily remove the custom module: modprobe -r custom_module
3. Apply the OpenSSL update: dnf update openssl
4. Rebuild the custom module against the new OpenSSL headers
5. Reload: modprobe custom_module
